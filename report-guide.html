PART BGitHubで公開・管理する

つくった資料を、GitHub Pagesで公開して、みんなで管理するための手順です。

4まず全体像

GitHubは、ファイルを置いておく「倉庫」です。倉庫に置いたHTMLを、GitHub Pagesという機能で、そのままWebページとして公開できます。

リポジトリ
資料をまとめて置く倉庫。資料シリーズごとに1つ作ります
コミット（Commit）
変更を保存すること。「いつ・誰が・何を変えたか」が履歴に残ります
GitHub Pages
倉庫の中のHTMLを、URLで見られるように公開する機能
公開URLの決まり方
https://アカウント名.github.io/リポジトリ名/フォルダ名/
アカウント名 リポジトリ名（倉庫の名前） フォルダ名

例：月次報告の9月分は、次のURLで開きます。index.html は省略できます。

https://gbpsupport-run001.github.io/runbird-inside-sales-report/reports/2026-09/
おすすめのフォルダ構成（月次報告の例）
/ ├─ index.html ← 月次の一覧（目次ページ） └─ reports/ ├─ 2026-08/index.html ├─ 2026-09/index.html └─ 2026-10/ ├─ index.html └─ payments/ ← 中にフォルダがあってもOK

月ごとのフォルダは reports の中にまとめます。月が増えても、いちばん上がごちゃごちゃしません。

5リポジトリを作って公開する

新しい資料シリーズを始めるときだけ必要です。すでにあるリポジトリに追加するなら、7へ進んでください。

  1. GitHubにログインし、右上の ＋ → New repository を押す
  2. Repository name に名前を入れる。英数字とハイフンで、月や年は入れず、runbird-inside-sales-report のように長く使える名前にする
  3. 公開範囲を Public にして、Create repository を押す
  4. Add file → Upload files から、最初のHTMLをアップロードして Commit changes
  5. リポジトリの Settings → Pages を開く
  6. Source が「Deploy from a branch」になっているか確認し、Branch を main、フォルダを / (root) にして Save
  7. 1〜2分待つと、同じ画面の上に「Your site is live at …」とURLが出る
注意Publicは、URLを知っている人なら誰でも見られます。お客様の個人情報や社外秘の数字は載せないでください。
6みんなで共同管理する
メンバーを招待する（管理者がやること）
  1. リポジトリの Settings → Collaborators を開く
  2. Add people を押し、相手のGitHubユーザー名かメールアドレスを入れる
  3. 候補から選んで追加する。相手に招待メールが届く
  4. 相手がメールの招待を承認すると、そのリポジトリを編集できるようになる
ポイント相手のGitHubアカウントが必要です。まだなければ、先に各自で無料アカウントを作ってもらってください。1つのアカウントを全員で共有すると、「誰が変更したか」が履歴で分からなくなるので、1人1アカウントがおすすめです。
権限の考え方

ざっくり、「資料を直せる人」と「設定を変えられる人」に分かれます。

管理者（リポジトリを作った人）
  • ○ファイルの追加・編集・削除
  • ○公開の設定（Pages）
  • ○リポジトリ名の変更
  • ○メンバーの招待・削除
招待されたメンバー
  • ○ファイルの追加・編集・削除
  • ×公開の設定（Pages）
  • ×リポジトリ名の変更
  • ×メンバーの招待・削除

資料の更新は、招待されたメンバーなら誰でもできます。設定まわりは管理者に任せる、と覚えておけばOKです。

7新しい月の資料を追加する（いちばんよく使う）
  1. パソコンのzipを右クリック → すべて展開。展開後のフォルダ（例：2026-10）を用意する
  2. GitHubで、reports フォルダの中を開く（URLが …/tree/main/reports の状態）
  3. 右上の Add file → Upload files を押す
  4. エクスプローラーから、外側の月フォルダそのもの（2026-10）を、画面にドラッグ＆ドロップする
  5. 一覧に 2026-10/index.html や 2026-10/payments/… のように、パスつきで出ているか確認する
  6. メッセージを入れて Commit changes を押す
  7. トップの index.html を開き、鉛筆アイコン（Edit）で、目次に10月分へのリンクを1行書き足してコミットする（既存の月の行を参考にする）
注意zipの中を開いたままドラッグすると、うまくいかないことがあります。必ず展開してから操作してください。
ポイントブラウザからのアップロードは、1回100ファイルまで・1ファイル25MBまでです。多い場合は、下の「github.dev」を使うか、数回に分けてください。同じ名前のフォルダがあると上書きされるので、先に reports の中を確認しましょう。
8ファイルを移動する・消す
移動する（ファイル名欄にパスを入力）
  1. 移動したいファイルを開き、右上の鉛筆アイコン（Edit）を押す
  2. 上のファイル名欄を、新しい場所に書き換える。例：2026-09-2/index.html → reports/2026-09/index.html（/ を入れると、フォルダが自動で作られます）
  3. 右上の Commit changes… → Commit changes で確定
注意移動先に同じファイルがすでにあると、エラーになります。置き換えたいときは、先に古いほうを削除してから移動してください。
消す

消し方は2つあります。

ファイル1つだけ
そのファイルを開き、右上の「…」→ Delete file
フォルダごと
そのフォルダを開き、右上の「…」→ Delete directory。中のファイルの一覧を確認してから、確定します
  1. 消したいファイル（またはフォルダ）を開く
  2. 右上の … から、Delete file（フォルダなら Delete directory）を選ぶ
  3. メッセージ欄はそのままで、Commit changes を押す
覚えておくと便利GitHubは、フォルダの中にファイルが1つもなくなると、空のフォルダを自動で消します。
ポイント消す前に、目次などからそのページへリンクしていないか確認してください。消しても、履歴から復元できます。
たくさんまとめて動かすなら「github.dev」が便利
リポジトリのページで、キーボードの .（ピリオド） を押すと、ブラウザ上でVS Codeのような画面が開きます。左の一覧で、フォルダやファイルをドラッグ＆ドロップで移動でき、右クリックでDeleteもできます。終わったら、左の「ソース管理」アイコンからメッセージを入れてコミットし、同期（Sync）してください。
9リポジトリ名を変える（管理者がやること）
  1. リポジトリの Settings → General を開く
  2. Repository name に新しい名前を入れ、Rename を押す
  3. 公開URLが、新しい名前に変わったことを確認する
注意名前を変えると、GitHub PagesのURLも変わり、旧URLのリンクは開けなくなります。社内で共有済みのURLやブックマークは、差し替えが必要です。変えるときは、みんなに一声かけてからにしましょう。
10公開URLを確認する・反映を待つ
  1. リポジトリの Settings → Pages を開き、「Your site is live at …」のURLを確認する（これがトップのURL）
  2. そのURLの後ろに reports/2026-09/ のようにフォルダ名を足すと、各ページのURLになる
  3. 公開が反映されるまで、1〜2分かかる。コミットの横が 黄色い点（反映中）→ 緑のチェック（完了） に変われば開ける

11注意点まとめ
📦 アップロードの上限
ブラウザからは、1回100ファイルまで・1ファイル25MBまで
🗜️ zipは展開してから
zipのまま、または中を開いたままドラッグしない
♻️ 同名フォルダは上書き
同じ名前のフォルダは上書きされる。先に reports の中を確認
🌐 Publicは誰でも見られる
お客様の個人情報や社外秘の数字は載せない
更新したら、最後にチェック
  • 公開URLで表示できた（スマホでも見た）
  • トップの目次に、新しい月へのリンクがある
  • お客様の個人情報が入っていない
  • チャットで「更新しました＋URL」を共有した
